# 待确认订单恢复页面

## 实现范围

桌台工作台新增独立入口，具有 orders.create 的当前员工可进入，不依赖某桌当前是否存在营业场次。页面读取上一轮加密订单日志，只处理当前服务、员工、设备及门店绑定的原请求；不重建商品参数、不生成新请求号。

- 默认进入仅加载本地记录，不自动提交或取消；查回调用 recoverOrder 默认只读1913。
- 原样重试需弹窗确认，说明可能真实成单并预留/扣减库存。控制器先查回，仅未观察到时原样调用1912。
- 终止需弹窗确认，调用1914。若服务器返回原请求已成单，显示成单，不显示终止成功。终止不是退单或退款。
- 展示桌台标识、原请求号、原请求金额及付款模式；不展示会员姓名/手机号/密钥。金额不作为付款凭证。
- 操作中禁用页面动作，防止重复点击。会话变更、组件替换、后台切换递增页面世代，清除可见列表与结果；旧确认不可发送，迟到结果不可展示到新会话。恢复前台重新加载本地记录。
- 网络异常保留原记录供再次查回。读取失败明确显示错误，不伪装为空、不输出原始异常或自行删除记录。确认/终止终态的删除仍由控制器严格匹配回执后执行。
- 简中、英文、繁中、泰语文案齐全；列表可滚动，操作行自动换行。

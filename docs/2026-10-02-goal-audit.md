## 本批实现与剩余验收

“后付款手机/柜台点单 → 按项实际出酒 → 柜台结账 → APP/收银同步”的三端实现和 MySQL 合成测试已完成，后端及收银已发布。下面仍是完整闭环的判定要求；自动测试和配套安装不能替代双端现场表现核验。

1. 继续共用 CommerceOrder/OrderLine、原 userAccount、桌台场次与价格快照；手机订单不冒充员工来源，身份码不授予付款权限。
2. 下单、部分交付、已付款和库存出库分别记录。未实际出酒的后付款单不能假写 issued；按本次交付增量扣批次与库存，同请求重放不重复扣库。
3. 支付、整桌结算和清台识别未出/部分已出/全部已出状态。付款时与交付已扣的数量对齐，不二次扣库；已出酒的未结账债务不可因取消/超时被抹掉。
4. 原有“提交即出库”的历史后付款订单继续识别真实库存流水，不重扣、不回补猜测数量。纯先付款仍保留付款前抢库存及未知渠道保留规则。
5. 覆盖单品售罄、部分交付、并发交付/付款、整桌组合、重复请求、失败回滚及双端通知；更新三端文档后统一发布。真实扣款/实际出酒不得用测试结果冒充。

本核对没有创建订单、交付、付款、清台或更改门店付款模式；不会把只读统计当作新流程现场验收。

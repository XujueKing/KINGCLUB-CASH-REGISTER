# 逐项上菜进度显示

订单明细现读取统一后端 1905 的 `servedQuantity`、`remainingQuantity`，简中/英文/繁中/泰文逐项显示已上与待上。数据为查询时快照，不改变订单付款状态；交付记录不证明已付款，历史交付仍需运营核对。

两字段都缺失表示旧后端没有提供交付记录，显示明确未知提示而不是零。单字段缺失、显式 null、布尔/字符串/小数、负数、超限或两数之和不等于下单量，拒绝该快照并显示读取失败。session 的 paymentTiming 一并保留供后续操作条件校验。

沿用订单页身份/场次/前后台失效守卫与 WebSocket revision 刷新机制，未加入本地推算或乐观已上状态。待上仅表示记录差值，不授权对已关闭/过期订单继续上菜。

本节点只接显示，不接上菜写入。后端 1919/1920 已注册且默认关闭；后续须先实现不可变原请求、加密持久化、独立员工/设备/门店绑定、先保存后发送、仅明确确认回执清除、未知状态保留与人工原请求恢复，然后开放上菜确认入口。不能因为当前累计数等于目标数就删本地未决请求。

验证：Flutter analyze 无问题；全量 234 项测试通过，2 项可选测试跳过（截图和未提供隔离 TLS 环境的互通测试）。新增数量解析与四语言界面测试，包括未知/异常数据、未付款但部分已上、已关台历史进度。测试数据只在 test 目录，不导入真实业务。

本次没有构建或安装新 APK，没有部署后端、执行真实交付、支付或清台，也不代表完整上菜功能验收。

# 交班对账：账源核对与接入缺口

状态：2026-09-30 本地源码核对；尚无交班实现、数据库迁移、超级接口或真实营业验收。本文不创建真实班次，不预设员工或钱箱归属。

## 已核对的统一后端

路径以 ccsop-service 为根。

| 业务 | 权威来源/现有实现 | 对账不能省略的区别 |
| --- | --- | --- |
| 单笔现金 | `src/kingclub/commerce/cashier-cash-confirm.ts`；migration 190 的现金回执、确认员工、确认时间 | 实收减找零才是该交易现金净流入，不能把实收全额计为营业额 |
| 整桌现金/渠道/余额 | migration 222 `kingclubCommerceTableCheckout`；`cashier-table-payment-receipt.ts` | 付款确认和订单结算是两个阶段；paid 尚未 settled 仍有已确认资金，不得在财务核对中消失 |
| 整桌订单分摊 | migration 222 `kingclubCommerceTableCheckoutAllocation`；`cashier-table-receipt-document.ts` | 父收款只计一次，子订单用于销售分摊，不能再累计成多笔渠道收款 |
| 余额退款 | `cashier-balance-refund.ts`；migration 211 `kingclubCommerceBalanceRefundReceipt` | 原收款保留，退款另列；平台现金与门店本金/赠送原路分开，不能把赠送退回当现金支出 |
| 门店充值收款 | migration 217 `kingclubStoreRechargeOrder`；`store-recharge-payment-confirm.ts` | paymentStatus confirmed 与 creditStatus credited 不等价；已收款待到账单必须单列，不能仅统计到账记录 |
| 门店充值入账 | `store-recharge-credit.ts`；`kingclubStoreBalanceLot` / `kingclubStoreBalanceMovement` | 本金与赠送分别进入批次，赠送不是渠道实收；充值和后续消费不能重复统计为同一笔外部收款 |
| 权限 | `cashier-authorization.ts` | 已有 shift.manage/report.read 权限枚举，不等于存在班次服务或当前员工已获授权 |

现有小票是已验证历史交易的展示投影，不是完整交班账本。尤其整桌小票要求已结算，而交班还必须展示已付款待结算、未知渠道状态和待退款等异常。不能分页累计 UI 列表作为总账，也不能从 WebSocket 通知金额累计；事件只触发重新读服务端。

## 实施时必须保留的边界

- 门店、币种、员工授权由服务端校验。只读报表不签发权限，不挤下会员 APP 登录。
- 时间窗口应由服务端冻结，并明确使用哪个业务时间字段。跨日退款不回写历史收款；查询范围不能仅用原订单创建日期。
- 支付渠道、平台现金消费、门店本金消费、赠送抵扣、充值本金实收、充值赠送分别展示。现金净收款不等于钱箱实盘余额，更不等于银行已结算金额。
- 父付款及退款按权威唯一记录去重；不把子订单内部 `table:` 引用认作新渠道交易。缺少账源、分页未读完或核验失败时，不出“已平账”结论。
- 初始备用金、现金存取、实际盘点、差额原因、交接双方和时间等钱箱事实当前未建模，不能用默认零补齐。
- 未决交易保留原请求，报表读取不能发起扣款、退款、核销或自动补差。
- 交班提交应持久原请求、冻结明细范围，重复提交幂等；交班后迟到结果需留独立更正/差异记录，不能悄悄改写已签认单据。具体截止与归属规则须随用户选择定稿。

## 待确认，不能擅自固化

已询问交接对象：按收银机/钱箱、员工个人，或门店统一营业班次。该选择影响唯一开放班次约束、收款归属和多人交接，尚未选择前不生成正式班次表或写接口。

后续需明确备用金/现金存取管理以及跨班未决交易归属。可以先做已授权范围内的只读账源核对，但不得把无班次归属的时间范围汇总标成“交班完成”。

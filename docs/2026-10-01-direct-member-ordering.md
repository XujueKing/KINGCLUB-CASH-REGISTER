# 入座直接点单

用户指出：入座后再次选择会员、再点“点单”，且姓名下显示长内部编号，现场操作冗余。

现流程为选桌、扫码、确认入座，然后直接进入刚入座会员的点单页。收到服务端确认后仍重新读取该桌当前场次名单；只有该会员仍在名单且可点单时才进入购物车，否则留在名单，不从扫码结果假定入座。已有会员的名单改为点击姓名直接进入点单，去掉选择圆圈和底部第二次点单按钮。名单、购物车标题与订单确认使用姓名和桌名，不展示内部 userAccount 或场次编号。

仅修改交互，购物车仍是本地草稿，正式提交继续使用原统一接口、原请求恢复、价格库存和权限校验。没有改写任何用户编号。历史核对已确认：旧版以 userAccount 作为用户标识；018 迁移另发 KM memberId，027 在部分手机号冲突场景增加 UM userAccount。该实现偏离原文档的单一 userAccount 要求，不能用“账户键与会员展示号”解释为满足要求，也不能用 UI 隐藏冒充数据库编号统一。完整证据见后端《2026-10-01-user-identifier-history-audit.md》；尚未执行身份迁移。

目标名单、购物车和入座 31 项测试通过，六文件静态检查通过。真实扫码识别及 V1 入座已在上一版本实机看到；本次直接点单交互需安装后核验，尚未产生测试消费单。

后续实机核验：ARM32 release 构建成功；核对当前安装包及候选签名一致后保留数据升级。名单仅显示姓名和进入箭头，已无内部编号与选择圆圈；点击已入座会员一次进入商品目录／购物车，顶部以桌名和姓名确认归属。候选测试商品已加入本地购物车，并打开最终确认页，未点击提交。正式创建未付款订单、APP 通知同步及测试后取消释放库存仍待具体商品金额授权和实测。

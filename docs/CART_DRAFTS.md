# 购物车草稿恢复：数据层进度

## 2026-09-29 本轮实现

`CartDraft` 是尚未提交的选择，不是订单请求。仅保存服务地址、员工/设备/门店、桌台/场次/会员、付款模式、CNY、保存时间、随机本地编辑版本及 SKU/数量/观察到的价格和版本。没有业务 requestId、凭据、会员昵称、商品名称或付款结果。局部数据不可修改，解码严格校验字段、整数量级、最多50行、不重复SKU及总价上限。

`CartDraftStore` 复用 `PlatformSecretStorage`，与待确认订单 `OrderJournal` 分键；最多100条、1MB，不自动逐出或明文回退。同 isolate 多实例串行读写，每次写入读回核对。保存必须提供读取到的原草稿（首次为空），旧编辑不能覆盖/删除新版；同员工不同场次不会互相替换，其他员工记录不展示且保持原样。损坏内容或存储异常保留原记录并报错，写后异常不被报告为成功。

恢复校验要求有效员工会话和点单权限、相同桌台/场次/门店/付款模式及仍可代点的入座会员，调用方必须提供重新查询的目录和场次。缺货、未知库存、价格/版本变化、商品缺失或重复目录均整份拒绝，不悄悄改价、删行或改数量。校验函数本身不访问网络，不能证明调用方传入的观察是最新的；仍必须由后续控制器执行真实查询和服务端下单复核。

## 验证与未完成边界

14项专项测试通过；全量333项通过、3项可选集成跳过；analyze无问题。测试存储是明确的内存替身，跨实例读回不是 Android 进程重启/Keystore验收。本轮没有修改后端或生产数据，没有构建安装。

当前尚未接入控制器或购物车页面，因此现有页面仍为内存草稿，不宣称已可断电恢复。下一节点必须一并实现：

1. 显式保存、恢复、删除入口和四语言说明；不得把磁盘草稿标成已下单/已锁价。
2. 恢复前检查本桌待确认订单，重新查询实际场次/会员/目录，处理分页、身份切换、实时更新及迟到响应。
3. 下单交接先持久化原 `PendingOrder`，再可靠移除对应可复用草稿，最后发送原命令。任何中断必须由原请求恢复流程接管；不得先发送再删草稿或凭本地删除认定订单成功。
4. 控制器与UI测试覆盖上述崩溃窗口、存储失败、后台/身份变化、离线和确认取消，再安排受控设备验证。

存储类不是权限或交易协调器；不能绕过原请求恢复直接对草稿自动生成并重发订单。完整生产目标保持不变。

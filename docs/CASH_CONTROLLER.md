# 现金控制器接线

StaffAuthController新增pendingCash、prepareCash、recoverCash、confirmCash、closeCash，复用独立员工加密SessionChannel，分别对接1915/1917/1916/1918。不使用会员会话或通用已付接口。后台元数据/开关仍默认关闭，本轮没有线上请求或真实交易。

- 准备须显式confirmed，先保存UUID/原金额并读回，再发送1915。准备返回只提供已知意图，进一步查回才取得当前可确认状态。
- 查回默认只读1917。只有未观察到且用户显式retryOriginalPreparation时，原样重发已存1915参数；不新建UUID、不自动重试确认。
- 员工明确已收现金后，先持久化实收金额，再查回。如果已确认则验证并结束；仍prepared且当前允许确认才调用1916。读失败、期限过期或回执不一致保持已收现金记录，禁止改成未收款终止。
- 明确未收款终止，先持久化不可逆决定，再查回与1918；可以处置到期prepared现金。已收现金、无已知意图或模糊状态不允许终止。
- 所有写决定均以完整原signature比较替换。每个await前后检查认证epoch/期限/权限，迟到网络响应在解析与清日志之前被拒绝。现金操作同控制器串行，连点拒绝CASH_IN_PROGRESS。pendingCash仅本地读取。

超时、注销与控制器重建均不清支付日志；重新认证后可用原请求查回。已确认结果只在原回执严格一致时清除记录，接口报错原样保留，不显示假成功。调用方仍须控制前后台交互、弹窗有效期及四语言提示；当前未接收银机按钮，不能宣称界面收款闭环。

新增11项控制器测试，以明确内存TEST_ONLY接口/存储替身验证每个网络发送时原请求/决定已落盘；覆盖确认和准备响应丢失、原请求只读恢复/显式准备重试、实收锁定、终止互斥、存储失败禁发包、读失败与期限过期保留决定、退出迟到结果、并发互斥，以及新控制器重建后只查原请求。它们不是安卓Keystore断电、公网HTTP/TLS、真实支付或终端验收。

验证结果：flutter analyze无问题，完整flutter test为194项通过、1项可选截图跳过。测试替身初次编译的closed字段与父类bool冲突已重命名修正；此问题未影响生产控制器。未构建或安装新APK，未操作线上数据库或渠道。

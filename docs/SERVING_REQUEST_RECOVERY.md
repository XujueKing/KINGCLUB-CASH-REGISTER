# 上菜原请求日志与会话控制器

`PendingServing` 固定服务入口、员工、设备、门店/桌台/场次/订单/商品行、下单量快照及原 UUID、观察数/累计目标数。严格整数、范围和字段校验，不包含会话密钥或会员资料。准备必须有有效 orders.serve 会话及显式确认；不允许减少或超量。

`ServingJournal` 复用平台安全存储 `pending_staff_serving_v1`，同 isolate 串行读写并读回核验，最多 100 条/100 万字符。相同服务入口的同订单商品行未决时，其他员工/设备也不能创建替代请求；只能原员工原设备原门店看到自己的记录。损坏数据、写入失败、达到容量均拒绝，不自动清理，不降级明文。退出/过期不删除未决记录。

`ServingResult` 只承认 1920 not_observed 或完整 confirmed 回执。confirmed 逐项核对请求号、归属、员工、交付前后数量、差值、剩余量和完整标志；其他人恰好把当前数量改到目标数不是本请求成功的证明。只删除严格匹配原命令的记录，未知或异常回执永久保留待核对。

控制器：

- `confirmServing`：原决定安全保存成功后才发送 1919，不自动重试。1919 必须返回匹配 confirmed 回执。
- `pendingServing`：仅当前有效员工会话可读取本人的未决请求。
- `recoverServing`：默认只调用 1920。仅当明确 `retryOriginal=true` 且查回 not_observed，才重发原 1919 参数，不生成新 UUID、不给实物再上一份。
- 同时只允许一个上菜操作；网络前后与持久化前后校验认证 epoch、会话到期与权限。身份变化或迟到响应不能显示新会话成功，不会无凭据清除原记录。

本节点测试包括：保存后发送、丢响应后新控制器查回、默认查询不重发、明确原请求恢复、并发拒绝、存储读回失败/写后异常、跨员工隔离、异常回执、到期/销毁后迟到响应。16 项专项通过；全量 250 项测试通过、2 项可选跳过，analyze 无问题。测试用存储/网络替身，不证明 Android Keystore 断电恢复或真实服务 HTTP 交易。

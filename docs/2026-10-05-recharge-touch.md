# 会员触屏充值

点击会员详情的充值，打开大金额键盘和门店档位按钮。点击“充多少、送多少”自动带入本金与赠送；手动改金额转为普通充值，赠送为零，不把旧档位的赠送带入新金额。金额最多两位小数，使用分提交。

底部“微信支付宝付款”共用付款码入口，扫码枪无需输入焦点，按码识别渠道。只有服务端确认余额入账才关闭并刷新会员详情。复用原充值准备、收款、查询和持久化原请求；未知结果查询原单，不新建重复收款。原始付款码不保存。现金收款需要员工确认已收到现金，使用同一充值记录与本金/赠送批次，断网重试查询原请求。现金充值退款显示“确认已退现金”，不会伪装成微信退款。

权限：微信、支付宝、现金分别校验本店 payment.wechat / payment.alipay / payment.cash，现金退款同时需要 payment.refund。更换员工或门店不沿用旧页面授权。

验证：充值键盘、档位及手输金额、取消现金、现金响应丢失后恢复、微信/支付宝自动识别及原会员页，共 6 项组件测试通过。ARM32 正式包构建成功，与既有应用证书一致。静态分析无错误或警告，仍有项目既有及同风格的花括号提示。

服务端 migration 332 已备份后部署，仅扩展原充值表渠道约束和原接口参数。真实数据库回滚事务验证现金充值、赠送、重复请求、现金退款，不保留测试资金记录。微信门店充值配置已核对；本店支付宝商户配置仍缺失，支付宝不能宣称已可实际收款。未发起真实扣款。

首次打包时收银机断连。用户接回后已核对 SUNMI 目标设备和已安装应用证书，与新版一致，使用 install -r 保留数据升级成功。实机进入会员充值，键盘及收款按钮完整显示，点击“充1000送100”正确填入本金1000和赠送100，未执行实际收款。门店目前存在两条相同金额的已启用档位，页面忠实展示配置，本次没有删除或改动档位。

## 架构决策

1. 超级接口负责可审计的查询与命令，沿用实际路径 `POST /supper-interface`（原协议拼写）。使用现有 AES-GCM、HKDF-SHA256、HMAC-SHA256 和防重放约定，不另造明文业务接口。
2. WebSocket 只用于已授权经营事件和刷新提示；收到事件后按门店权限查询权威快照。不能仅凭推送显示收款成功。断线恢复重新获取快照，陈旧数据显示离线状态。
3. 员工会话必须具有用途隔离、门店范围、操作权限与撤销机制。服务端从已验证会话确定操作人；请求里的账号／门店字段不是授权依据。收银凭据不能访问会员私聊、个人资产操作或物业业务。
4. 金额使用整数分；价格、优惠、库存、结算及会员扣款全部由后端确定。会员余额使用现有资产账本，但必须验证归属、支付授权及幂等，不能凭手机号查询结果直接扣款。
5. 付款、核销超时进入“结果待确认”，先按原业务请求号查单／查核销；禁止自动重复扣款、重复核销。现金确认也必须形成真实后端流水和当班审计。
6. 第三方应用密钥仅在服务端配置。门店与商户／POI／授权范围由服务端映射，未开通渠道不可伪造成功。团购验证、确认核销、结果核对、撤销与差错处理分阶段实现。

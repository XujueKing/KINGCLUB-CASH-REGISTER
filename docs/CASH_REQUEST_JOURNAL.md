# 现金原请求与安全日志

本节点只新增客户端命令/回执模型与持久化，不接收款按钮或网络请求，不代表收银机已能收款。后端现金准备1915、确认1916、查回1917、终止1918已在统一服务实现并默认禁用，端到端与真机验收仍待完成。

PendingCash生成一次安全随机UUID，绑定HTTPS服务地址、员工、安装设备、门店、订单和预期金额/CNY。只保存业务请求，不保存API密钥或refresh token。准备前检查本地会话有效及payment.cash，真正权限与价格仍由后端核验。金额使用整数分，1至100000000。

现金准备响应严格匹配后端8字段，即便intentStatus=confirmed/closed也必须进一步查回，不把准备结果当付款/终止回执。查回匹配原requestId/订单/门店/意图/金额。支付回执严格核对11字段、确认员工、cash:intentRef、实收及找零；终止回执严格核对10字段、原请求、员工及未收现金声明。未知/畸形/不一致结果均不清日志。

本地状态按原请求单向推进：未发→已知意图→明确已收现金（锁定实收金额）或明确未收款终止。两项决定互斥，不能超时后改实收或从已收改终止。对已知intent返回not_observed视为不一致，需复核。服务器结果若与本地明确决定矛盾，不自动当终态丢弃记录。

CashJournal使用既有PlatformSecretStorage，键pending_staff_cash_v1，版本1，最多100条/100万字符，同isolate静态队列串行。每次写后读回完全比对；失败不允许调用方继续发送。升级命令使用原signature比较替换，拒绝旧快照覆盖新决定。每个服务/门店/订单只保留一个未决请求，包括另一员工留下的未决请求；换员工不展示旧明细，也不允许覆盖。完整记录损坏时保留原始内容并停止，不自动清空或回退明文。

只有与持久化完整命令匹配的已付款或已终止CashResult可acknowledge；not_observed/prepared/needsLookup保留。没有退出清理或TTL删除入口。测试使用明确内存替身验证契约，并非安卓Keystore断电恢复验收；同进程多isolate/多进程写日志不在当前支持范围。

后续控制器必须在调用1915前保存原请求、1916/1918前保存明确决定，过期/换员工/服务切换后丢弃迟到回调。超时只查原请求，不自动重发、新建UUID或修改现金金额。UI需展示应收/实收/找零及明确收妥/未收现金确认，不能自动交易。打印、交班、混合付款、退款与第三方渠道不由此日志实现。

验证：新增21项专项测试，完整flutter test为183项通过、1项可选截图跳过；flutter analyze无问题。首次测试发现准备回包字段数误写9，已按后端实际8字段修正并完整重测。Dart格式化及花括号修复仅修改新文件；本轮未构建/安装新APK、未发送生产网络请求、未执行真实收款。

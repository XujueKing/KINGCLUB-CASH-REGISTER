# 订单现金准备入口（2026-09-29）

1905订单只读投影读取严格布尔cashierOrder；旧服务字段缺失按false，null/数字/字符串拒绝。来源不是支付授权。对应后端提交23698fab，本轮没有部署服务器或启用接口。

当前员工具有payment.cash、场次open/clearing、服务端来源明确为员工订单、状态pending、CNY、D加11位订单号、金额不超过100000000分时显示准备入口。服务端仍独立检查会话、权限、原订单/金额/库存状态、通道排他与接口门禁。

## 流程

1. 先读取当前身份的安全存储原请求；同订单已有请求直接进入现金恢复页，不创建新请求号。读取失败清除明细并显示读取失败，不继续收款。
2. 新请求弹窗显示订单号和金额，明确只是准备、不代表已付款；取消不发送。
3. 明确确认后复用现金控制器：先保存原请求再调用1915。本页不自动重试，成功或异常均转原请求恢复页。准备失败且未产生本地请求时恢复页可为空，不显示收款成功。
4. 恢复页先查询1917，再显式确认实收1916或未收款终止1918。金额固定、收妥/终止互斥、终态凭证验证沿用已验证的数据层。不是整桌合并结算。

身份、桌台/场次、实时revision或前后台变化会使确认失效并关闭弹窗；迟到准备结果不进入新上下文。操作期间禁用分页/刷新/返回及重复准备；页面被父组件移除仍由控制器保留原请求。支持控制器实例替换时解绑旧监听。

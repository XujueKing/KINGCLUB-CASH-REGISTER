## 2026-10-10 已上架筛选及开关

“所有库存”后增加“已上架”，与分类和搜索组合，本地筛选不请求接口。表格列为商品/规格、账面、预留、可售、零售价、上架状态；啤酒整组零售价仍按半打/一打显示。预留是已下单待出库占用，保留以说明可售数量。

选择商品后，右侧上架开关沿用 shift.manage。店长修改后提交手机审批，待审显示目标状态及“待审批”，开关保持当前生效值且不能重复提交；配置中的超级管理员直接生效。未知请求复用原请求核对和取消机制，不长期阻塞新操作。一次 set_listing 返回回执和小库存页，不另发整页读取。

手机设置 → 商品上架可审批或直接操作；客户端隐藏按钮只是交互，统一后端验证真实员工、门店、商品版本及超级管理员配置。上下架不会变更库存、采购报价、零售价或历史订单；本次仅此库存内入口，不扩展套餐和销售包装编辑。

## 2026-10-10 凭证更新与页面读取

库存整页仍通过 K261006002017 / kingclub_inventory_command 一次读取，不拆分供应商或清单请求。同一门店、员工、登录会话及权限范围共享短期只读显示快照；返回库存页先显示已有清单，再后台核对，写操作回执直接更新快照。库存金额、采购、入库等最终结果仍由服务端校验。

凭证更新保留当前员工和头像的显示投影，更新期间禁用交互并关闭旧 API；更新失败仍撤销本地身份。商品页只在实际登录范围改变时清空，不因普通身份通知、定时续期或退到后台清空分类与卡片。大响应 AES-GCM 解密和 JSON 解码在后台 isolate 完成，仍验证原协议认证标签；自动测试覆盖更新、后台切换、身份撤销、库存快照返回及大响应篡改拒绝。

已完成原签名 ARM32 保留数据升级。实机库存首次整页读取 2061ms；返回库存的截图在后台请求仍进行时已显示清单，商品图命中本地磁盘。该数值为接口调用耗时，不代表首帧或所有网络环境；没有执行库存、付款或订单写操作，既有待确认库存请求保留。

左栏「库存」进入六个页签：库存、盘点、借还酒、采购、流水、供应商。采用现有浅色、深绿按钮和触摸数字键盘；切页签不重拉接口，操作返回直接更新数据，库存事件到达后静默核对。

首次使用：先登记供应商，再做「首次清点」，按实物输入数量与柜格；这会调整账面差异，不是在原测试库存上再加一次。盘点草稿按门店/员工保存在本机，未填写商品不改动。每周和人员交接使用同一盘点流程，可填交接人员备注。

借酒：选商品、数量 → 扫借酒人会员码。归还：在借还酒页选原单、数量、整瓶/已开瓶/破损及柜号 → 扫收酒人会员码。整瓶恢复可售，其他仅记去向。身份扫码不扣会员余额。

采购：系统按预警与在途数量列出建议，老板调整数量、供应商、成本后确认；到货点击入库，可分次收。预警策略在商品详情设置。供应商底单由统一 API 上传后关联采购或收货，在流水中查看图片或扫描短时链接查看 PDF。

柜格与存酒共用门店设置，右上角柜格图标可维护；占用中的柜格不可删除。所有库存仍与收银、APP 共用原余额和批次。服务端接口及 AI 调用文档见后端 `05-接口与权限/2026-10-06-inventory-management.md`。

未知历史成本显示「成本未知」，不会当作零成本；已发生的历史批次不因首次清点填写新成本而改写。采购确认只记本店采购单，不自动向供应商发送消息或付款。

# 2026-10-09 本店零售价

库存管理选择商品后点击“修改零售价”。左侧显示当前本店售价、各供应商原报价与单位、折算采购单价、供应商建议零售价；未提供的建议价明确显示“未提供”。右侧用触摸数字键盘输入新价。“采用”仅填入建议价，保存才生效；右上关闭不保存。仅具有 price.adjust 权限的员工可操作。

保存复用 K261006002017 的 retail_price 动作，一次返回回执和更新后的页面。携带打开时的商品版本，避免覆盖其他人改价。只修改本店以后点单使用的售价，历史成交价、进货报价及批次成本保持原值。服务器保留原价、新价、操作员及时间用于追溯。

现场库存整页含完整供应商采购目录，实测约 812KB，加密后 base64 响应超过原 1MB。仅 K261006002017 的响应上限调整到 2MB，请求及其它接口继续保持 1MB；仍逐块检查大小、验证加密和 TLS，不省略商品或拆成多次请求。超限/default/请求限制已通过传输测试。
# 2026-10-10 库存持久化与改价解锁

本日追加修复：之前只验证了打开改价弹窗，实际保存被超级接口漏登记的 priceCents／saleUnitRef 参数拒绝。服务端迁移 444 补齐契约；客户端把 PARAM_SCHEMA_VALIDATION_FAILED 视为明确未执行，不保留假待确认锁。弹窗直接显示安全的失败原因，可在原弹窗重试；结果未知时先核对原 UUID，已成功保存同一价格直接确认，不重复改价。

新改价请求带 view=stock，迁移 446 让单品和整组过程直接返回小库存页面，旧请求仍兼容原整页返回。啤酒只销售整组时，商品详情显示半打／一打报价，不显示隐藏的单瓶基础价。改价仍选择确切销售规格，库存换算规则不变。

供应商“采购备选”按 50 条分页读取，分类及搜索在服务器执行；缓存按门店、员工、权限、供应商和查询条件加密保存，重开先显示已有页面再核对版本。完整供应商目录不再为该弹窗重复下载。服务器实测旧大目录 514653 字节，新页 31587／34692 字节，未变响应 225 字节。

商品管理与手机上架审批的最新确认规则已写入 AGENTS.md；该新流程与本轮改价／采购分页修复分开验收，不能把快捷改价当成店长提交／超级管理员手机审批已经完成。

库存首页现在请求 K261006002017 的 `context/view=stock`，一次返回本店库存、价格、对应供应商报价及页签摘要；完整采购备选商品只在打开采购选择时请求 `view=full`。旧客户端不传 view 时仍兼容原整页契约。

库存显示清单按服务地址、门店、员工和权限范围加密保存到本机。再次进入先显示已有清单，后台带 `knownVersion` 核对；内容未变化只返回版本确认，不清空列表。实时事件使库存页静默更新并失效采购目录缓存。缓存只用于显示，提交仍走服务器实时权限、版本和库存校验。

旧请求待确认不再禁用改价入口。读取页面同时核对该员工的原请求；已完成或已取消自动解除本地等待。点击改价／重新编辑时复用 `resolve_pending`：已执行的读取回执，尚未执行的记录原请求取消，阻止迟到请求再执行，然后打开新的改价面板。网络结果未知仍保留原请求，明确业务拒绝或发送前会话失效则不长期锁住页面。

# 库存管理

左栏「库存」进入六个页签：库存、盘点、借还酒、采购、流水、供应商。采用现有浅色、深绿按钮和触摸数字键盘；切页签不重拉接口，操作返回直接更新数据，库存事件到达后静默核对。

首次使用：先登记供应商，再做「首次清点」，按实物输入数量与柜格；这会调整账面差异，不是在原测试库存上再加一次。盘点草稿按门店/员工保存在本机，未填写商品不改动。每周和人员交接使用同一盘点流程，可填交接人员备注。

借酒：选商品、数量 → 扫借酒人会员码。归还：在借还酒页选原单、数量、整瓶/已开瓶/破损及柜号 → 扫收酒人会员码。整瓶恢复可售，其他仅记去向。身份扫码不扣会员余额。

采购：系统按预警与在途数量列出建议，老板调整数量、供应商、成本后确认；到货点击入库，可分次收。预警策略在商品详情设置。供应商底单由统一 API 上传后关联采购或收货，在流水中查看图片或扫描短时链接查看 PDF。

柜格与存酒共用门店设置，右上角柜格图标可维护；占用中的柜格不可删除。所有库存仍与收银、APP 共用原余额和批次。服务端接口及 AI 调用文档见后端 `05-接口与权限/2026-10-06-inventory-management.md`。

未知历史成本显示「成本未知」，不会当作零成本；已发生的历史批次不因首次清点填写新成本而改写。采购确认只记本店采购单，不自动向供应商发送消息或付款。
# 2026-10-06 商品分类筛选

库存和盘点复用点单的商品分类，按用户最新要求放在商品列表左侧，竖排并可上下滑动，选中项使用白底及深绿侧线；不再放顶部横排分类。右侧保留名称／规格搜索、库存不足及无库存组合筛选。各规格单列，切换分类保留盘点草稿，不发起接口请求。不符合当前筛选的已选商品清除选择，防止操作错货。

库存不能套用点单的上架范围：APP 专属、停售商品仍可查看及盘点。分类来自原 kingclubCommerceCategory，lowStock 由统一库存过程按可售库存和预警值返回；已有在途采购不掩盖当前库存不足。
# 2026-10-09 本店零售价

库存管理选择商品后点击“修改零售价”。左侧显示当前本店售价、各供应商原报价与单位、折算采购单价、供应商建议零售价；未提供的建议价明确显示“未提供”。右侧用触摸数字键盘输入新价。“采用”仅填入建议价，保存才生效；右上关闭不保存。仅具有 price.adjust 权限的员工可操作。

保存复用 K261006002017 的 retail_price 动作，一次返回回执和更新后的页面。携带打开时的商品版本，避免覆盖其他人改价。只修改本店以后点单使用的售价，历史成交价、进货报价及批次成本保持原值。服务器保留原价、新价、操作员及时间用于追溯。

现场库存整页含完整供应商采购目录，实测约 812KB，加密后 base64 响应超过原 1MB。仅 K261006002017 的响应上限调整到 2MB，请求及其它接口继续保持 1MB；仍逐块检查大小、验证加密和 TLS，不省略商品或拆成多次请求。超限/default/请求限制已通过传输测试。

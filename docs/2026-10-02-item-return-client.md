# 收银端退库取消协议与恢复（进行中）

新增 `PendingItemReturn`、`ItemReturnResult` 和 `ItemReturnJournal`，将原桌台／场次／订单／商品、数量、已上数、原金额、出酒轮次、实物确认及 UUID 保存在既有安全存储。先校验并保存、读回核对，再调用统一接口；失败不删除原请求。客户端数量与价格只用于一致性核验，不授权库存或金额变更。

`StaffAuthController.confirmItemReturn` 调用 `K261002001969`；`recoverItemReturn` 用完整原参数调用 `K261002001990`。查询不到结果仍保留记录，不自动重发；明确重试时先查询，再提交同一 UUID 和同一参数。只有匹配原范围、员工、数量／金额算式和库存回执的成功响应才能清除记录。重启恢复按服务地址、员工、设备和门店隔离。

已有未确认上菜操作会阻止发起同商品退库。退库与上菜提交共用控制器的串行操作锁。已上退回要求退款权限，本地保存失败时不发送网络请求。

验证：15 项新协议／存储／控制器测试，连同上菜控制器和四语言召回 UI 共 27 项通过；覆盖保存后发送、写入失败、权限、数量边界、损坏响应、原请求不匹配、未观察到结果、丢失响应后重启查询和显式同号重试。分析无错误或警告，控制器存在原有格式提示。

## 后续增量：明细弹窗与恢复入口

已上且未付款的商品，在明细“召回”中可选择“退库并取消商品”；检查点单、上菜、退款权限及活动场次，选择数量后显示减少的应付金额，以“实物已退回，确认取消”单个按钮确认，无额外勾选框。已付款商品保持不可用，不能用本接口绕过单品退款。

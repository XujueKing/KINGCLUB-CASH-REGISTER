# 会员扫码接收与桌台操作

现场反馈：扫码枪有滴声，但扫码页没有输入；选中输入框后重扫仍无输入。设备安装商米扫码服务，原应用仅使用 TextField 接收键盘输入，没有接收厂商扫码广播。

按[商米官方扫码器说明](https://file.cdn.sunmi.com/SUNMIDOCS/Barcode-Scanner-User-Guide-20201202.pdf)接入 ACTION_DATA_CODE_RECEIVED 的 data 字段，通过原生 EventChannel 传到当前会员识别页面。仅前台且页面订阅时注册接收，离开页面取消，进入后台不转发；不记录扫码原文。广播本身不可信，仍必须经过会员码格式、会话与服务端身份校验，不作为支付或入座成功依据。

键盘式输入保留：进入扫码页自动聚焦，完整会员码输入后短暂防抖自动识别，支持带或不带回车的扫码枪；尾随空回车不清除刚识别的会员。避免自动弹出软键盘占据收银屏幕。

桌台选中改为同页右侧紧凑操作区，保留桌台网格，侧栏明确显示所选台名；状态、金额、消费明细和入座操作集中在侧边，无需进入原大卡片中间页。刷新期间旧快照上的操作禁用。

验证：20 项会员输入、桌台与工作台测试通过，五个目标 Dart 文件静态检查通过。覆盖广播输入、无回车输入、重复回车、后台忽略扫码、离页取消订阅，以及选台后网格仍可见。

ARM32 release（含原生扫码桥）构建通过，核对原安装与候选签名一致后保留数据升级 SUNMI；员工会话恢复。实机确认紧凑侧栏与桌台网格同时显示，扫码页面的商米广播接收器已注册。向本应用发送一次不存在会员对应关系的测试广播码，页面自动显示识别失败，验证原生至 Flutter 的接收链路；没有生成入座或消费记录。已请现场重新打开手机实时会员码重扫，真实硬件扫码和会员识别结果仍待确认。

## 实际扫码盒与后续检查

现场重扫仍无反应。用户照片确认实际外设为收钱吧小白盒 D33M（广州尚臣电子），USB 连接；不能因收银机安装商米服务就认定此外设使用商米广播。当前 Android USB 枚举仅有主控与 USB 打印机，输入设备列表没有外接键盘或扫码设备。已请求将小白盒直接换接收银机另一 USB 口，再核对枚举；尚未确认该型号输出协议，不执行恢复出厂或盲扫其他型号设置码。

另用延迟返回的会员查询复现了键盘输入焦点丢失：查询期间禁用输入框，返回后不能继续接收下一次键盘扫码。现补上查询成功、失败、清除及回前台时的焦点恢复，并避免回车完成动作自动移走焦点；后台、离页或无权限时不抢焦点。该回归测试修复前失败、修复后通过，会员身份测试共 10 项通过，两份目标 Dart 文件静态检查通过。本次焦点修改尚未安装到设备，也不代表 D33M 真机问题已解决。

后续实机进展：换 USB 口后新增 `USBKey Module`（VID 0x2F50、PID 0x0301），Android 列出其键盘输入节点。用户确认有输入，但提示未能确认会员。对一次真实扫描仅在内存统计格式，收到 37 字符、符合 `KC:M:[0-9A-F]{32}`；没有输出或保存原码。目标会员的只读服务端检查显示会员有效、审核通过，但没有未过期的登录会话，不能绕过身份码会话校验。已请用户重新登录手机再验证；这尚不能证明整个识别链已经成功。

焦点修复 `6f13076` 已完成 ARM32 release 构建，核对候选和现有签名一致后 `install -r` 成功，应用已启动，未卸载或清除数据。

会员重新登录后，服务端只读校验通过，现场扫码页面实际显示“已确认当前会员身份”；当前没有昵称时显示占位，后端显示名对齐另行修复。用户明确要求操作简单：去掉入座的两个独立勾选，扫码展示会员后直接点“确认入座 · 桌名”。该按钮统一表达收银员对本会员、本桌的入座确认，保持旧接口字段，不将扫码自动当作入座，不宣称新增自动预约匹配。未知结果仍查原请求，服务端权限／场次／重复入座校验保留。

简化入座已通过 18 项身份及入座测试、两文件静态检查与 ARM32 构建，签名一致后保留数据安装成功。真实入座和点单同步尚未验收。

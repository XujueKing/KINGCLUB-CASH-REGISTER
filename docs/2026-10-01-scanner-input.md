# 会员扫码接收与桌台操作

现场反馈：扫码枪有滴声，但扫码页没有输入；选中输入框后重扫仍无输入。设备安装商米扫码服务，原应用仅使用 TextField 接收键盘输入，没有接收厂商扫码广播。

按[商米官方扫码器说明](https://file.cdn.sunmi.com/SUNMIDOCS/Barcode-Scanner-User-Guide-20201202.pdf)接入 ACTION_DATA_CODE_RECEIVED 的 data 字段，通过原生 EventChannel 传到当前会员识别页面。仅前台且页面订阅时注册接收，离开页面取消，进入后台不转发；不记录扫码原文。广播本身不可信，仍必须经过会员码格式、会话与服务端身份校验，不作为支付或入座成功依据。

键盘式输入保留：进入扫码页自动聚焦，完整会员码输入后短暂防抖自动识别，支持带或不带回车的扫码枪；尾随空回车不清除刚识别的会员。避免自动弹出软键盘占据收银屏幕。

桌台选中改为同页右侧紧凑操作区，保留桌台网格，侧栏明确显示所选台名；状态、金额、消费明细和入座操作集中在侧边，无需进入原大卡片中间页。刷新期间旧快照上的操作禁用。

验证：20 项会员输入、桌台与工作台测试通过，五个目标 Dart 文件静态检查通过。覆盖广播输入、无回车输入、重复回车、后台忽略扫码、离页取消订阅，以及选台后网格仍可见。

ARM32 release（含原生扫码桥）构建通过，核对原安装与候选签名一致后保留数据升级 SUNMI；员工会话恢复。实机确认紧凑侧栏与桌台网格同时显示，扫码页面的商米广播接收器已注册。向本应用发送一次不存在会员对应关系的测试广播码，页面自动显示识别失败，验证原生至 Flutter 的接收链路；没有生成入座或消费记录。已请现场重新打开手机实时会员码重扫，真实硬件扫码和会员识别结果仍待确认。

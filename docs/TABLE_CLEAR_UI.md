# 清台界面与原请求恢复

工作台仅向有 table.clear 权限的员工显示清台请求入口；有效桌台的当前场次可进入清台核对页面。界面展示桌名、桌台及场次，必须二次确认顾客已离座、现场已整理；按钮不是付款、退款、删除订单或本地释放桌台操作。最终条件由服务器1921检查，客户端不使用分页订单或汇总金额决定是否结清。

页面先读取当前员工本设备安全日志。同场次已有未决记录、读取失败、权限缺失、访问凭据过期或后台状态不允许新建请求。发送期间禁止重复点击，发送尝试后本页不再创建替代请求。异常不展示成功，不删除未决记录或自动重发。

恢复入口初次只读本地日志；点击查询调用控制器1922。仅收到 not_observed 后显示恢复按钮，二次确认后控制器重新查询并按原场次、原请求号重发。历史 confirmed 只表示原场次结果，不证明当前桌台为空。返回工作台重新读取1904，不修改本地桌台为空，已有新场次仍从服务端展示。

认证通知、工作台实时revision更新及后台切换使待确认弹窗失效，迟到结果不发布到失效页面。控制器仍独立校验员工会话及原请求。四语言覆盖简中、繁中、英文、泰语；错误不回显内部异常。读取日志失败不同时显示“无待处理记录”。

验证：17项widget测试通过，覆盖四语言确认/取消/恢复、权限/到期/存储失败、同场次未决、重复点击、丢响应、认证/revision/后台失效、历史清台后新场次仍保留，以及返回重新读取。全量299项通过，2项可选集成跳过；Flutter analyze无问题。网络/存储为测试替身，不是真实清台HTTP或Android断电恢复验收。

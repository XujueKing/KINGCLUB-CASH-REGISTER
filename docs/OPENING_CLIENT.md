# 员工开台端内接入（2026-09-29，进行中）

统一后端：1907 开台上下文、1906 提交开台、1908 原请求回执查询、1909 终止原未决请求。
已实现查询、显式提交、恢复与终止控制器，尚未连接开台 UI。

- 门店来自当前已验证员工会话，不接受页面任意指定；本地 table.open 仅作体验门禁，服务端必须重新授权。
- 查询前后检查会话与有效期，退出、刷新或替换身份后丢弃迟到结果。
- 上下文保留营业日、付款模式、规则版本及门槛、服务端写开关、已有场次。
- configured 与 manual_default 明确区分；默认人工规则不是已配置规则。
- 必须人工确认到店和预约核对；上下文不代表预约已核验、座位预留或开台成功。
- not_observed 表示尚未查到，绝不能转换为“请求失败”或自动换新请求号。
- confirmed 只代表原请求的已提交回执，不证明场次当前仍在营业；后续需重新查询桌台。
- cancelled 表示原请求已被服务端永久终止，不是桌台场次已关闭；原请求不可重发，新开台需刷新上下文。
- 回执会员列表不可变；校验门店、桌台、请求号、场次号、日期和重复会员，异常统一返回无业务明细的错误码。

已新增 `OpeningJournal` 与不可变 `PendingOpening`，复用平台加密存储（不启用损坏自动重置或明文降级）。
记录原 UUID、不可变参数以及服务地址/门店/员工/设备归属，不保存认证密钥或刷新令牌。
独立存储键不会被员工退出清除；同一应用 isolate 内跨实例串行读改写，同一服务/门店/桌台只保留一个未决请求。
最多 100 条记录，满额拒绝新增而不是淘汰旧记录；读取损坏、版本未知、写入失败或回读不符均阻止成功返回。
匹配原请求、会员清单、营业日和付款模式的 confirmed 回执，或匹配请求/门店/桌台的 cancelled 结果可移除记录；not_observed 不移除。

已接入 StaffAuthController：submitOpening 在保存完成后才发送 1906，发送前后重新检查员工会话；
pendingOpenings 只读出当前身份绑定记录，recoverOpening 默认只查询 1908。
只有显式 retryOriginal 才会在 not_observed 后发送原 UUID/参数；查到 confirmed 或 cancelled 则不再发送。
一次只运行一个提交/恢复操作；退出或刷新导致迟到结果被丢弃，不将旧结果显示给新员工。
成功响应需按真实回执解析并匹配记录后才能清除；超时、接口错误、畸形回执或存储失败都保留恢复路径。
尚未连接开台 UI；崩溃、超时、刷新后的恢复不自动重提或清除未知结果。
cancelOpening 要求显式 confirmed，按本地原记录发送 1909，不接受任意门店或桌台参数。
仅根据服务端 confirmed/cancelled 终态移除记录；普通错误码不能证明请求永久停止。
取消超时、not_observed、畸形/矛盾响应均保留本地记录，下一次通过 1908 恢复。
跨员工交接当前只阻止覆盖，不向新员工展示原会员资料；授权的交接恢复入口仍待实现。
不支持多进程同时写此存储；回读一致不等于硬件断电持久性验收。未完成真机/真实后端集成，
